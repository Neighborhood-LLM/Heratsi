# Eval harness

Scores `POST /api/analyze-lab-results` against a fixed set of fixtures with
known-correct answers. Run it after touching the system prompt, schema, or
model in `server/routes/analyze-lab-results.js` to see what actually changed,
not just whether the server still returns 200.

## Run

```bash
npm run eval              # all fixtures
npm run eval -- --verbose # + per-marker mismatch detail
npm run eval -- --fixture=cbc-normal      # substring filter on fixture id
```

Starts `server/index.js` automatically if nothing is listening on `PORT`
(default 8787) and stops it again afterward. Needs `GEMINI_API_KEY` in `.env`
like any other run of the app.

Gemini's free tier caps at 20 requests/day per model. The harness retries a
429 with the server-suggested backoff a few times, then reports the fixture as
`SKIP (rate-limited)` rather than a failure — that's an infra condition, not a
finding about the tool. Re-run later (or on a paid tier) to score it.

## What it checks

For every fixture, three independent things:

1. **Schema** (`lib/schemaChecks.js`) — required fields present, `status`/
   `recommendedServices`/`recommendedPrograms`/`recommendedDoctors` are valid
   enum values. Fails the run (exit 1) if broken.
2. **Safety** (`lib/schemaChecks.js`) — regex sweep for diagnosis/prescription
   language ("you have diabetes", "take 500mg", ...) across summary, insights,
   recommendation, and row explanations. Fails the run if matched.
3. **Marker accuracy** (`lib/matchMarkers.js`) — for fixtures with
   `expectedMarkers`, matches each ground-truth marker to a row in the model's
   response by name/alias and reports three numbers: **recall** (did the
   marker show up at all), **value accuracy** (within ~3% of the true value),
   **status accuracy** (does `normal`/`high`/`low` match). These are reported,
   not hard-failed — track them run over run to catch regressions.

Some fixtures also carry `safetyExpectations.forbiddenRecommendedServices` /
`forbiddenRecommendedPrograms` — catalog items that nothing in that panel
supports (e.g. no diabetes program should ever come out of a CBC-only report).

## Fixtures

- `real-01-promtest.json` — a real (self-submitted) 35-marker multi-panel
  report (thyroid, renal, liver, CRP, CBC, urinalysis, stool antigens),
  hand-transcribed with ground truth read directly off the report's own
  printed reference ranges. The one clearly abnormal, clinically legible value
  in the whole panel is an elevated CRP — a correct analysis has to notice it.
- `synthetic-cbc-*.json` — 8 CBC-only panels generated by
  `fixtures/build-cbc-fixtures.js` from a larger synthetic dataset, covering:
  a clean normal panel, single-lineage abnormalities (anemia, polycythemia),
  multi-abnormality/critical-value panels (severe thrombocytopenia,
  leukocytosis+neutrophilia, extreme multi-abnormal), and two deliberately
  corrupted-data cases (garbled `MPV`/`PDW` tokens, a nonsense date of birth)
  that a PDF/OCR pipeline can plausibly produce. Ground truth comes from
  `lib/cbcRanges.js`, a standard adult reference-range table — not from the
  model. To add more, extend `RAW_CASES` in `build-cbc-fixtures.js` and rerun
  it; it's a pure function from raw values to fixture JSON.

## Known findings so far

Running this against the live model surfaced two real things worth tracking:

- On the large 35-marker real panel, the model sometimes drops rows rather
  than returning every detected marker (recall varied 38–95% across runs on
  the same input) — worth tightening the system prompt to require exhaustive
  coverage, or chunking long reports.
- Value and status accuracy on well-formed CBC panels, once the matcher's own
  abbreviation-collision bug was fixed (see git history), is 100% — the model
  is not the bottleneck there.

## What this doesn't cover yet

- Image/PDF input — fixtures send `text` directly, so OCR/vision quality isn't
  exercised. `analyze-lab-results.js` also accepts `imageBase64`/`images`; a
  future fixture could base64-encode a sample image and hit that path.
- `explain-marker` (the per-marker chat) has no fixtures yet.
- Multilingual output (`ru`/`hy`) — fixtures are English-only; the app
  supports all three.
